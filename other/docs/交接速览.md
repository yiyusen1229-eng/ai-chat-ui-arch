  没点过隔 3 天再提）；菜单「帮助 → 检查更新」用 `?force=1` 强制查一次。

17. **情绪标签要当「不可信输入」处理**：模型经常整句不写 `<emotion>`（实测 5 句里 2~4 句没有），
    而且改词表顺序只会把偏置挪到另一个词（把毒舌排第一，平常句就被标成毒舌）。
    现在 `split_emotion` 会在缺标签时按台词形态猜，来源记在 `LAST_EMO_SOURCE`
    （`tag/inferred/default/override`），`api_chat` 打一行「情绪标签推断/缺失」。
    **别再把它改回「没标签就 calm」**——那会让参考音频和立绘表情一起瘫在 calm 上。
18. **语音名字读错先看 `characters/<角色>/pronunciation.json` 在不在**：读音替换只读这份数据，
    代码里不写死任何角色名。角色包导出/导入**不带**它，重整过角色文件夹就会丢（2026-11-05 就是这么丢的）。
    映射表按 mtime 缓存，补完不用重启。
19. **台词是双语输出，别再单独去翻**：模型一次给
    `<emotion>…</emotion><action>（中文动作）</action><ja>日语</ja><zh>中文</zh>`，
    `split_bilingual()` 拆开 —— ja 给 TTS（`speak_ja`）、zh 给字幕。
    只有模型**没给 `<zh>` 或不像中文**时才走 `translate.py` 兜底（云端 → 本地 Hy-MT2）。
    谷歌免费端点实测 **429**，别浪费时间接；云端翻译必须 `reasoning_effort=none`
    （否则 `max_tokens` 会被 reasoning 吃光、`content` 为空）。
    人名靠角色文件夹的 `translation_glossary.json`（`{"to_zh": {"春树": "春希"}}`，长键优先）纠正。
20. **回想重播慢先看「缓存命中」**：TTS 缓存 key = `text|lang|emotion|参考音频签名|模型签名|参数`
    （文件在 `build_env/cache/tts`，启动只**修剪**不删空）。2026-11-22 改成**先查缓存再切权重**：
    命中时日志是「TTS 缓存命中」、耗时约 0.0s；没命中才去加载/切换权重（3~7 秒）。
    参考音频一改（导入新参考），签名变 → 旧缓存全部失效，第一遍重放会重新合成一次，属正常。
    重播必须用这句**当时的情绪**（`row.dataset.emo`），写死 `neutral` 会永远 miss。

21. **「字幕长、语音短」先分清是合成截断还是文本本身长度差**：合成端 `cut5` 不截断
    （实测 1 句 1.56s / 2 句 3.24s / 3 句 6.70s；`cut0` 才会截断，别改）。
    `text_parse.ja_clean()` 以前**无条件按第一个句号取第一句**、还会从句中逗号砍，
    两句台词会被砍成半句——已修。旧版字幕是另一次翻译的产物，字数本来就对不上；
    现在字幕是模型自己写的 `<zh>`。
22. **「素材已更新」狂弹不是推送，是轮询把运行时数据当成了素材**：后端 2 秒扫一次
    assets + 当前角色目录算签名，前端 4 秒轮询 `gen` 变了就弹。角色目录里的
    `sessions/`（自动存档/缩略图）和 `memory/standing.json` 聊天时一直在变，于是几秒弹一次。
    现在 `hotreload.SKIP_DIRS`（sessions/cache/_deleted/logs/…）与 `SKIP_FILES`（standing.json）
    不参与签名，前端提示也节流到 15 秒一次；放真素材（portrait/voice）仍然立刻生效。

23. **语音端口约定**：共享进程 **9880**、翻译服务 **9881**、角色进程池从 **9882** 起。
    池基端口以前写成 9881 和翻译服务撞车 → 角色子进程绑不上端口、请求打到翻译服务失败 →
    永远退回共享进程反复切权重，用户只感觉「重放要重新加载」。分配端口会跳过已占用的
    （崩溃留下的孤儿进程会一直 listen）；就绪判断是 HTTP 健康检查（404 也算就绪，只把 5xx/
    连接失败当没起）；`tts_client.stop()` 会收掉池子进程。别把这三条改回去。

24. **场景匹配是三层的**：`scene_cg.time_hint() / weather_hint() / detail_hint()` 从「玩家这句 +
    这轮动作描写」读时段 / 天气 / 地点细节（模型写了 `<scene>` 标签时以标签为准），
    再 `match(scene, prev, time_hint=, weather_hint=, detail_hints=)` 挑变体。细节词表直接从
    `res/assets/cg/index.json` 的 `state` 长出来，**加素材不用改代码**。
    标签还是对不上时，`api_chat._judge_scene()` 会让主模型从完整场景名里挑一张（关思考，
    `max_tokens=40`，只在玩家这句有地点线索时触发，约 +0.5~1 秒）。

25. **特殊场面的语音细节不写进文档 / README / 更新日志 / 提交信息**（用户 2026-11-22 明确要求；
    代码注释可以留技术说明）。这条清理过一次，别再加回来——包括"为了说明删掉了什么"这种备注。

26. **导入参考音频用 `program/tools/import_voice_refs.py`**：文件名 `场景_行号_第几遍` →

    缺文本的加 `--asr`（本地 faster-whisper large-v3，**必须走 CUDA float16**，CPU 跑 95 条要 40 分钟以上）。
    导入后跑 `ref_vad_scan.py <情绪> --char <角色>` 写 `_refaudio.json`。
    3.5~7.5 秒带文本的参考最稳；>8 秒的只会在纯拟声句时被选中。

27. **更新检测的两个前提，缺一个就是「只弹到旧版 / 点了没用」**：
    ① **发版必须同时改** 仓库根 `version.json` 和 `program/src/version.py` —— 11-22.1 只写了
    日志、漏了这两处，远端 `version.json` 停在 11-10.1，老客户端最多只能「看到」11.10
    （`tools/test_update.py` 现在守一致性，不一致会红）。
    ② **打包版（exe）不能原地更新**：`updater.detect()` 见 `sys.frozen` 就返回
    `mode=portable / can_auto=False`，`apply()` 直接拒绝。冻结后**别用 `__file__` 算根目录**
    （会指到 exe 上一级，以前把更新写进旁边另一套源码副本，exe 一个字没变）。
    ③ `version.json` 别用记事本存（带 BOM 会让 `json.load` 抛异常，代码已按 `utf-8-sig` 兜住）。

## 会话摘要（2026-11-22 收尾）

这一轮的主线是「**模型给的东西不靠谱时，别让程序替它猜错**」——三处都是同一个毛病：
拿上一轮的状态套这一轮。按「读这一节能不能直接接手」写：

1. **场景匹配补了三层线索**（最重要）：以前模型只写 `<scene>学校大门口</scene>`（不写时段），
   匹配就沿用上一张背景的时段 —— 白天去学校接成晚上的校门口。现在
   `scene_cg.time_hint/weather_hint/detail_hint` 从「玩家这句 + 这轮动作描写」读线索
   （取最靠后的提及），`match(..., time_hint=, weather_hint=, detail_hints=)` 用它补标签；
   模型写了标签就以标签为准。细节词表从 `index.json` 的 `state` 自动长，加素材不用改代码。
2. **加了「模型判场景」兜底**：玩家这句有地点线索时，额外问一次主模型「此刻在哪儿」，
   给它完整场景名表挑最接近的一张（卫生间洗漱 → 自己的公寓（洗手台）；放学回家 →
   回家的路（晚上）（路灯亮着））。必须关思考，否则 40 token 全被 reasoning 吃光。
3. **配音**：整段旁白不再送合成（以前把「（她在路灯下停了一瞬…）」也念出来）；
   读档最后一条按「旁白 / 他人 / 自己」区分；特殊场面用对应的参考音频（细节按第 25 条不写进文档）。
4. **动作文本改回字模**：`wt-nav.js` 的 `renderActionImage()` 用 `/api/text?chars_per_line=N`
   烤成**多行** PNG，宽度按 `TEXT_SCALE` 缩放、高度随行数长 —— 字号恒定、和对话框一致、
   白字带描边。别再退回 `uitext.js`（那套是单行图，长句会被挤小）。
5. **语音回放慢是真 bug**（不是缓存坏了）：① 以前先切权重再看缓存 → 改成先查缓存；
