# 多角色同场与导演系统 · 设计文档

> 状态：**讨论稿，尚未实现**。本文只记录设计与约定，不含代码。
> 讨论原文见 [`多角色与导演_讨论原文.md`](多角色与导演_讨论原文.md)（逐字记录，未做任何改动）。

---

## 一、目标

把「单角色一问一答」扩展成两种能力：

1. **多角色同场**：同一场景里可以有多个角色，各自的台词由**各自的模型**生成；
2. **导演系统**：一个专门负责推进剧情、安排节奏、调度发言者的 AI。

玩家只给大致框架（"接下来两人剑拔弩张，随后爆发激烈争执"），细节由导演填补与执行。

---

## 二、四种状态

| 自动 | 多角色 | 导演做什么 | 输入框 | 谁写台词 |
|---|---|---|---|---|
| 开 | 开 | 推剧情 + 写剧本 + 调度 | 隐藏 | 各角色自己的模型（龙套由导演写） |
| 关 | 开 | **只调度**：谁先反应、对谁反应、是否同时 | 显示 | 各角色自己的模型 |
| 关 | 关 | 不启动 | 显示 | 当前角色 |
| 开 | 关 | 推剧情 + 调度主角与当前角色 | 隐藏 | 当前角色 + 主角（"你"由导演写） |

自动模式 = 玩家不输入 = 开始写小说。

## 三、角色与档案

### 3.1 三类角色

| | 常驻角色 | 龙套（路人） |
|---|---|---|
| 由谁写台词 | 角色自己的模型 | **导演直接写** |
| 角色包 | 有 | 无 |
| 角色卡 | 有（进导演上下文） | 无（一行描述） |
| 能否被"咨询" | 可以 | 不行 |
| 配音 | 有语音素材就配 | 不配 |
| 进记忆书 | 进（她自己视角） | 不进 |
| 能推进剧情 | 可以 | **不可以**，只能反应 |
| 名字显示 | 有 | 有（`路人A：「……」`，导演临时起名） |

龙套的额外约束：

- 导演维护一份**临时演员表**（同一"店员"在后续拍里保持一致）；
- 龙套不能主动引发新事件，只能对当前局面做反应/提供信息；
- 龙套不能知道只有角色才知道的秘密。

### 3.2 角色卡（给导演看的，不是角色包）

放在角色包里，只在多角色模式提交给导演：

```
characters/<id>/
  card/
    director.md      # 150~300 字
```

内容分两半：

| 静态（写进卡文件） | 动态（不进卡） |
|---|---|
| 性格 3 条、口吻 3 条、**绝对不会做的事** | 当前对在场者的态度（敌视/别扭/亲近） |

动态部分从 `relations.json` 按当前场景注入：导演拿到的 = `静态卡 + 本场关系一行`。

**缺失规则**：角色没有 `card/director.md` 时，**拒绝把它加入多角色模式**，并提示补写该文件。

卡里记录源包哈希，包改了卡没改时提示"卡可能过期"。

### 3.3 主角卡

在**特殊模式**里做一个独立编辑页供玩家配置（性格 3 条、说话方式 3 条、绝不会做的事、称呼习惯）。

```
player/
  card/
    director.md
```

生效场景：

| 场景 | 作用 |
|---|---|
| 自动模式 | 导演按它写"你"的台词与动作 |
| 多角色模式 | 角色模型对"你"的反应有参照 |

### 3.4 称呼

| 谁 | 管什么 | 怎么决定 |
|---|---|---|
| 导演 | 叙述里怎么称呼主角 | 从存档上下文里读；读不到默认用「你」 |
| 角色模型 | 台词里怎么称呼主角 | 角色自己按关系/口癖决定（和纱会说「あんた」「お前」） |

## 四、导演契约

### 4.1 结构分层

```
大纲（一句话～一段）        ← 玩家给的框架，或导演自拟
 ├ 第一卷
 │   ├ 第一章
 │   │   ├ 幕1  ← 生成单位
 │   │   └ 幕2  ← 按需生成
 └ …
```

- 大纲当场生成一次；
- 卷/章只是结构，可在扩写某幕时才决定；
- **幕是生成单位**，拍是播放单位。

**大纲不入存档**。读档后大纲丢失，导演可能重新发挥、走到另一个故事 —— 这是接受的取舍。

### 4.2 幕长

由**导演自己判断**写多长，只限制最大字数：

| 档 | 拍数 | 字数 | 输出 token | max_tokens |
|---|---|---|---|---|
| 小幕 | 6~8 | 300~400 | ~260 | 400 |
| 中幕 | 10~14 | 600~800 | ~520 | 800 |
| 大幕 | 20~30 | 1200~1800 | ~1000 | 1600（分 2~3 段） |

- 硬上限：单幕 **2000 字**（可调，范围 800~4000，界面上给按钮）
- 到上限时不是中途截断，而是要求它在最后 200 字内落到自然停顿处
- 大幕分多段时：**段边界只能落在旁白/动作之后**；最后一段必须"收在悬念上"，不许总结

### 4.3 导演对每一幕先报计划

```
{ 预计字数, 分段数 }
```

程序据此分配 max_tokens 与分段数。

### 4.4 分段生成的衔接

第 2 段会带上「上一段结尾 200 字」作为上下文；**这 200 字只进提示词，不进对话框**。

副作用处理：模型容易原样复述接缝处最后一句 → 程序做去重（新段开头与上段结尾的最长公共前缀超过 15 字就削掉）。

### 4.5 导演的权限

**不设权限范围**。想要约束就在"剧情方向"里写；不写就自由发挥。
不满意靠存档回退（没存档则自认）。

## 五、生成与播放

### 5.1 队列在后端

```
后端：演出队列
 ├ 已生成未播放的行（文本 / 说话人 / 语音是否就绪）
 ├ 播放指针
 └ 已播放的行 → 才进回想
```

已生成但未播放的文本**不送入回想界面**。

### 5.2 缓冲上限

后台最多领先画面 **1 幕**（单幕上限 2000 字，所以最多领先约 2000 字）。

### 5.3 跳过

点击界面 / 右下角快进图标 / 鼠标滚轮向下 = 跳到下一条（前提是已生成）。

分层：

```
这一条还有下一页 → 先翻页
这一条已翻完     → 跳到下一条
```

跳过后**不能往回**，回看只能走回想界面。

### 5.4 跳过时的语音规则

| 当前播放 | 跳到 | 行为 |
|---|---|---|
| 语音行 | 语音行 | 立刻打断，播新的 |
| 语音行 | 非语音行 | **不打断**，旧语音继续 |
| 语音行 | 非语音 → 非语音 → 语音 | 到有语音那条时才打断 |
| 无语音 | 语音行 | 直接播 |
| 连跳多条且都无语音 | — | **等旧语音自然播完** |

### 5.5 预合成

文本一入队，后端**立刻**合成所有已生成行的语音（按顺序，一次一条，已缓存的跳过）。
优先级：下一条要播的最高；跳过/中断时取消当前合成、重排。

### 5.6 输入框的出现时机

队列没播完时**不出输入框**，必须点击/滚轮全部读完才出。
不做"放弃未读"按钮——想停只能读完或退出。

### 5.7 存档

- **没有自动存档**（现有代码里每轮的 `auto` 槽在新设计里删掉）；
- 存档只写「截至当前显示的那一句」，未读的队列一律不写；
- 播放中允许存档（存到当前句）；
- 存档之后继续往前读，**存档不会跟着更新**（下次读档回到存档那一句，后面读过的丢失）；
- 退出程序：内存全丢（包括未存档的已读对话）。

"继续游戏"随之没有自动数据可读，改为读最近一次手动存档或去掉。

## 六、上下文隔离与防 OOC

### 6.1 每个角色看到什么

```
她自己的人设 + 私有记忆书 + 对在场者的态度
+ 公共最近 K 轮原话
+ 导演给她的**这一拍任务**（含红线）
```

**不给全剧本**，只给"这一拍要发生什么 + 不能做什么"。

### 6.2 三件套

| 机制 | 作用 |
|---|---|
| **角色卡** | 导演看到的是 150~300 字压缩卡，不是角色包 → 不会替角色演，也不会写出角色不可能的反应 |
| **按需咨询** | 导演拿不准时问角色一句（"雪菜提三年前的演唱会，你会怎么反应？"），角色模型带完整包回答，输出一句话，成本很低 |
| **事后自检** | 角色生成时附带 `comply`：做不到就返回 `false + why`，导演改一次；还不行换人接话（旁白带过），不死循环 |

### 6.3 并行反应

反应拆三层：

| 层 | 是什么 | 谁生成 | 何时 |
|---|---|---|---|
| **立场 stance** | 此刻想要什么、情绪、戒备、打算做什么 | 角色模型 | 局面实质变化时（一拍开始时） |
| **增量 delta** | 听到别人这句话后，"要不要改刚才的想法" | 角色模型 | 每次别人行动之后（一句话） |
| **表达 utterance** | 说出口的台词 / 动作 | 角色模型 | 轮到她行动时 |

- "并行"发生在 **stance 层**（一拍开始时所有在场角色并行生成），台词仍顺序执行；
- 角色连说多句时，其他人每句之间都收到 delta（可以产出"无声反应"，写成旁白）；
- `overlap` 标记：几条同时基于同一快照生成、互相看不见 → 抢话/打断。

### 6.4 角色之间只共享"行为"，不共享"内心"

角色只看得到别人说了什么、做了什么表情，看不到别人的心理活动。既符合小说真实感，也天然避免串味。

### 6.5 防震荡

1. **张力曲线**：每拍给定张力目标，delta 只能往曲线方向走；
2. **预算**：整段有轮数预算，每拍扣；
3. **settle 规则**：连续 2 次 delta 后局面无不可逆变化 → 强制推进（换场景/抛事件/skip）。

## 七、成本与参数

按实际使用（cloud `deepseek-flash`）实测：中文约 **1 字 ≈ 0.65 token**，综合单价约 **¥0.75 / 百万 token**。

| 幕规模 | 单次输入 | 输出 | 单幕成本 |
|---|---|---|---|
| 小幕 | ~9k | ~260 | ≈ ¥0.007 |
| 中幕 | ~10k | ~500 | ≈ ¥0.008 |
| 大幕 | ~11k | ~950 | ≈ ¥0.010 |

- 多角色模式下每个发言角色各加一次调用，约为上面的 2 倍；
- 成本不设硬闸，界面上显示「本场已写 N 字 / 花费」，由玩家自行把控。

## 八、待定与风险

| 项 | 状态 |
|---|---|
| 幕上限默认 2000 字，界面可调 800~4000 | 已定 |
| 大幕分段时带上"上一段结尾 200 字" | 已定（不进对话框，需去重） |
| 删除自动存档后的"继续游戏" | 待定 |
| 跨角色记忆隔离（D 选项） | 已讨论未定稿：场景化存档 / 可见性标记 / 摘要隔离 |
| 关系网 | 未做，先靠"本场关系一行" |
| 非当前角色配音 | 依赖各角色 `voice/` 素材 |

### 风险

1. 幕内分段写大幕时，模型在接近输出上限处容易"赶工收束" → 需收尾检测；
2. 角色卡与角色包会脱节 → 卡里记源包哈希并提示过期；
3. 导演自由发挥可能走到玩家不喜欢的剧情 → 只能靠存档回退；
4. 预合成占用本地 GPU 时间，短时间大量生成会排队。
